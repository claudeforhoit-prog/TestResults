# 성능 리포트 생성기 (perfreport)

케이스 정보 파일(CSV 또는 엑셀)과 성능 데이터 폴더를 지정하면 케이스별 성능 리포트를 만든다.
산출물은 케이스마다 docx 1개와, 케이스·VM·지표를 골라 비교하는 반응형 HTML 뷰어(테스트 그룹마다 1개)다.
docx 에는 그 실행 구간에 수집된 지표 전부를 분류별 그래프로 싣는다. 지표 역할을 지정하면(3.2) 역할 순서로 싣는다.
Windows PC 한 대에서 인터넷 연결 없이 동작한다.

## 1. 빠른 시작 (견본)

1. `run_gui.bat` 을 실행한다.
2. `케이스 정보 파일` 에서 `samples\sample_cases.xlsx` 를 고른다. DRM 이 엑셀 파일을 암호화하는 PC 에서는 `samples\sample_cases.csv` 를 고른다.
3. `데이터 폴더` 에 `samples\sample_data` 를 지정한다.
4. `리포트 생성` 을 누른 뒤 `결과 폴더 열기` 로 docx와 html을 연다.

견본은 합성 데이터다. 호스트 2대에 VM이 4대씩 있고, 케이스는 3건이다.
- `CASE-A`: 호스트 esx01(VM `esx01-vm01`~`04`), 기본 설정. 비교 기준
- `CASE-B`: 호스트 esx01, 튜닝 설정. 같은 호스트에서 다른 시간에 실행
- `CASE-C`: 호스트 hv-node7(VM `app-a`, `app-b`, `db-main`, `batch`), 기본 설정. VM 이름 규칙이 달라 케이스 CSV의 `VM` 열로 VM을 지정한 예

## 2. 준비물

### 2.1 케이스 정보 파일 (CSV 또는 엑셀)

| 열 이름 | 필수 | 예 | 설명 |
| :-- | :-- | :-- | :-- |
| 케이스명 | 필수 | `CASE-A` | 리포트에 쓰는 이름. 중복 불가 |
| 설명 | 선택 | `기본 설정 (기준)` | 시험 조건 |
| 호스트 이름 | 필수 | `esx01` | 이 호스트의 VM 기록만 쓴다. 여러 호스트는 `;` 로 구분 |
| 잡 시작 시각 | 필수 | `2026-01-05 10:00:00` | 그래프 가로축의 0초 |
| 잡 종료 시각 | 선택 | `2026-01-05 14:00:00` | 이 시각까지를 실행 구간으로 쓴다. 비우면 자동 감지(2.4) |
| VM | 선택 | `app-*;db-main` | 이 케이스에 쓸 VM 이름 또는 패턴. 비우면 호스트 이름으로 찾는다(2.3) |
| 테스트 그룹 | 선택 | `tuning` | 같은 그룹의 케이스를 HTML 하나에 모은다. 그룹마다 HTML 1개 |
| 종료 기준 VM | 선택 | `*app01;*app02` | 잡 종료 시각을 비운 케이스에서 종료를 판단할 VM(2.4). 비우면 창 화면의 `종료 기준 VM` 값을 쓴다 |

- 첫 줄의 케이스가 비교 기준이다. 다른 케이스를 기준으로 하려면 화면의 `기준 케이스` 칸에 이름을 적는다.
- 엑셀 파일(.xlsx)을 그대로 쓴다. `케이스` 시트가 있으면 그 시트를, 없으면 첫 시트를 읽는다. 날짜 형식 셀과 빈 행도 읽는다.
- CSV는 UTF-8과 ANSI(CP949) 모두 읽는다.
- DRM 으로 암호화된 엑셀 파일은 읽지 못한다. 엑셀에서 `CSV UTF-8` 형식으로 저장해 그 CSV 파일을 쓴다.
- 시각은 `2026-01-05 10:00:00`, `2026/01/05 10:00`, `2026-01-05 오전 10:00:00` 형식을 읽는다.
- 시각은 데이터 파일과 같은 시간대로 적는다. 프로그램은 시간대를 바꾸지 않는다.
- 빈 양식: `samples\cases_template.xlsx` · `samples\cases_template.csv`, 작성 예: `samples\sample_cases.xlsx`

### 2.2 데이터 폴더

성능 데이터 파일을 한 폴더에 모은다. 하위 폴더도 읽는다. 여러 케이스의 기간이 한 파일에 섞여 있어도 된다.
파일마다 들어 있는 VM · 호스트 · 시각 범위를 색인(`사용자 폴더\.perfreport\file_index.json`)으로 저장해 두고, 케이스마다 실행 구간과 VM이 겹치는 파일만 읽는다. 데이터가 쌓여도 두 번째 실행부터는 바뀐 파일만 새로 확인한다.
프로그램이 파일마다 형식을 판별하고, 모르는 형식의 파일은 건너뛰고 로그에 이름을 남긴다.

| 형식 | 판별 기준 | 프로파일 |
| :-- | :-- | :-- |
| VCF Operations VM 지표 CSV export | `Name`, `timestamp` 열 | `profiles\inputs\vcf_ops_vm.yaml` |
| 직접 만든 CSV | `Time`, `VM` 열(선택: `Host` 열) | `profiles\inputs\generic_csv.yaml` |
| Key:Value 텍스트 로그 | 줄에 `Timestamp:` 와 `Hostname:` 이 있음 | `profiles\inputs\kv_text_log.yaml` |

### 2.3 케이스의 VM을 고르는 규칙

호스트 이름 규칙은 환경마다 다르므로, 케이스의 VM은 다음 순서로 정한다.
1. 케이스 정보 CSV의 `VM` 열에 값이 있으면 그 VM만 쓴다. VM 이름이나 패턴을 `;` 로 구분해 적는다. 예: `app-*;db-main;batch`
   - 이름을 정확히 적은 VM(`db-main`)은 호스트와 관계없이 쓴다.
   - 와일드카드(`*`, `?`)로 고른 VM은 `호스트 이름` 의 호스트에 있는 VM만 쓴다. 실행 구간의 상위 호스트 정보(아래 표의 열, 모든 데이터 파일)로 다른 호스트에만 있다고 확인된 VM은 뺀다.
   - 상위 호스트 정보가 어느 파일에도 없는 VM은 와일드카드로 골랐어도 쓴다.
   - 시험 중 vMotion 으로 호스트가 바뀐 VM은, 실행 구간에 그 호스트에 있었던 적이 있으면 옮긴 뒤의 기록까지 모두 쓴다.
2. `VM` 열이 비어 있고 데이터에 상위 호스트 열이 있으면, 그 값이 `호스트 이름` 과 같은 VM
3. 둘 다 없으면 VM 이름이 `호스트 이름` 으로 시작하는 VM (예: 호스트 `esx01` → `esx01-vm01`)
   - 호스트 이름 바로 뒤에 숫자가 이어지면 다른 호스트로 본다. 예: 호스트 `esx1` 에는 `esx10-vm01` 을 넣지 않는다.
   - 호스트 이름 뒤에 바로 글자가 이어지는 이름도 쓴다. 예: 호스트 `node7` → `node7app01`, `node7app02`, `node7db01`
   - 호스트 이름은 대소문자를 가리지 않고, 도메인을 붙인 이름(`esx01.corp.local`)도 같은 호스트로 본다. 이때 VM 이름은 짧은 이름(`esx01`)으로 시작하는지 본다.

상위 호스트 정보는 아래 열에서 읽는다. 대소문자, 밑줄, 하이픈은 가리지 않는다.

| 형식 | 상위 호스트 열 |
| :-- | :-- |
| CSV | `Summary\|Parent Host`, `Parent Host`, `ESX Host`, `ESXi Host`, `ESX Hostname`, `ESXi Hostname`, `ESX`, `ESXi`, `VMHost`, `Host`, `Host Name` |
| Key:Value 로그 | 위와 같은 이름의 키 (예: `ESXHost:esx01`) |

- VM 이름은 호스트끼리 겹치지 않는다고 본다. 같은 이름의 VM이 여러 호스트에 있으면 두 VM의 기록이 하나로 합쳐진다.
- VM 하나에는 호스트 표기 하나를 붙인다. 그 VM이 케이스의 호스트에 있으면 케이스 정보에 적은 호스트 이름으로 표기한다.

VM 이름 규칙에 기대어 다른 호스트의 VM끼리 자동으로 묶지 않는다. 다른 호스트의 VM끼리 비교할 때는 뷰어에서 직접 고른다(4.1).

### 2.4 실행 구간과 종료 시각 자동 감지

- 그래프와 TC 정리 파일에는 잡 시작 10분 전부터 종료 10분 후까지 싣는다. 그래프에는 잡 시작(0초)과 종료 시각에 세로 점선을 긋는다.
- 통계(평균, p95, 최대)는 잡 실행 구간(시작~종료 시각)만 쓴다.
- 잡 종료 시각을 비우면 종료 기준 VM 의 잡 종료와 CPU 사용률로 종료 시각을 정한다.
  - 종료 기준 VM: 케이스 정보의 `종료 기준 VM` 열, 그 열이 비어 있으면 창 화면의 `종료 기준 VM`(명령은 `--end-ref-vm`)에 적은 VM 이름 · 패턴이다.
    둘 다 비어 있으면 케이스의 모든 VM 을 본다. 예를 들어 TAT 를 재는 잡이 도는 VM 만 적으면, 다른 VM 에서 계속 도는 잡 때문에 종료 시각이 늦어지지 않는다.
  - 1순위, 잡 TAT 원장(2.8): 종료 기준 VM 에서 잡 시작 앞뒤 10분 안에 시작한 잡 가운데 가장 늦게 끝난 잡의 종료 시각(`PSEndTime`)
  - 2순위, CPU 사용률: TAT 원장에 종료 기준 VM 의 잡이 없을 때. 종료 기준 VM 이 여러 대면 가장 늦게 끝난 VM 이 기준이 된다.
    - 신호: 종료 기준 VM 들의 같은 분 CPU 사용률 최댓값을 5분 이동 중앙값으로 고른 값
    - 기준값: 5%와, 실행 중 신호 p95의 10% 중 큰 값
    - 종료 시각: 잡 시작 5분 뒤부터 보아, 신호가 기준값 미만으로 10분 이상 이어지기 시작한 분
    - 유휴 구간 없이 데이터가 먼저 끝나면 데이터 마지막 시각을 쓰고, 문서에 그 사실을 적는다
  - TAT 원장으로 정했을 때도 CPU 사용률로 본 유휴 시작 시각을 함께 적어 둘을 비교할 수 있게 한다.
- 감지한 종료 시각과 판정 근거는 케이스 문서 1절 표에 적는다.

### 2.5 수집 끊김 점검

리포트를 만들거나 TC를 정리할 때마다 잡 실행 구간 안의 수집 공백을 점검한다.
- 기준: 수집 시스템·VM마다 표본 간격(중앙값)을 구하고, 그 2.5배 또는 간격+60초를 넘는 공백을 끊김으로 본다.
- 함께 찾는 것: 잡 시작 뒤 수집이 늦게 시작된 경우, 잡 종료 전에 수집이 멈춘 경우, 실행 구간에 데이터가 없는 VM
- 결과는 케이스 문서 1절 표(`수집 점검` 행)와 Appendix 의 데이터 가용성 절(`수집 끊김 점검` 표)에 적는다.

### 2.6 TC별 정리 폴더

원본 파일을 TC 구분 없이 한 폴더에 두고, 케이스 정보에 따라 TC마다 필요한 부분만 잘라 정리할 수 있다.

```
perfreport.exe split <케이스정보.xlsx> <원본폴더> <정리폴더>
perfreport.exe run <케이스정보.xlsx> <원본폴더> --split <정리폴더>     (정리 + 리포트)
```

- `정리폴더\<케이스명>\` 에 원본과 같은 형식(열, 표기)의 파일을 저장한다.
- 파일 이름은 `<케이스명>-<종류>-<정리한 날짜>.<확장자>` 다. 종류는 파일 내용으로 정한다.
  - `ops`: VCF Operations 지표 export. 예: `TC-108-ops-20261110.csv`
  - `tat`: 잡 TAT 원장(2.8)에서 그 케이스에 연결된 잡의 행. 예: `TC-108-tat-20261110.csv`
  - `phase`: phase 소요 시간 CSV(2.7)에서 그 케이스에 연결된 잡의 행. 예: `TC-108-phase-20261110.csv`
  - 그 밖의 로그: `<케이스명>-etc-<번호>-<날짜>`. 예: `TC-108-etc-01-20261110.log`
  - 같은 종류가 여러 파일이면 종류 뒤에 번호를 붙인다(예: `TC-108-ops-01-20261110.csv`, `-ops-02-`). 번호 순서는 구간 안 첫 시각 순서다.
  - `manifest.csv` 에 정리 파일 이름과 종류, 원본 파일 이름, 행 수, 첫·마지막 시각을 적는다.
- 형식을 등록하지 않은 로그(위 종류도 아니고 리포트가 읽는 형식도 아닌 CSV · 로그)는 줄마다 시각과 VM · 호스트 이름을 찾아 etc 로 저장한다.
  - 남기는 줄: 시각이 실행 구간(앞뒤 10분 포함) 안이고, 그 TC 의 VM 이름이나 호스트 이름이 들어 있는 줄. 시각이 없는 줄(여러 줄짜리 기록의 다음 줄)은 바로 앞 줄을 따른다. CSV 는 첫 줄(머리글)도 남긴다.
  - 읽는 시각 표기: `2026-01-05 10:00:00`, `2026-01-05T10:00:00+09:00`, `2026/01/05 10:00:00`, `05 Jan 2026, 10:00:00`, `Jan  5 10:00:00`(연도는 케이스 연도).
    시간대 표기(`Z`, `+09:00`)가 있는 시각은 이 PC 의 현지 시각으로 환산하고, 그렇게 했다는 것을 `case.txt` 에 적는다.
  - 시각이나 VM 이름이 없는 파일은 어느 케이스의 것인지 정할 수 없어 넣지 않는다.
  - 리포트(문서 · HTML)에는 쓰지 않는다.
- 실행 구간(앞뒤 10분 포함) 안의 행 중 아래 행만 남긴다. 원본에 다른 호스트의 기록이 섞여 있어도 된다.
  1. 그 TC의 ESX 호스트 자신의 기록: 행의 대상 이름이 `호스트 이름` 과 같은 행
  2. 그 TC의 VM 기록: 리포트와 같은 규칙(2.3)으로 고른 VM의 행. 리포트와 TC 정리에는 같은 VM이 들어간다
- 행의 대상 이름은 형식마다 정해진 열이다: VCF Operations CSV 는 `Name`, Key:Value 로그는 `Hostname`, 직접 만든 CSV 는 `VM`. 이 열에는 VM 이름이 있어도 되고 ESX 호스트 이름이 있어도 된다.
- `case.txt` 에 케이스 정보, 저장 구간, 남긴 VM과 호스트, 정리한 날짜, 구간 안에서 뺀 행 수를 적는다.
- 같은 TC를 다시 정리하면 폴더를 새로 만든다(덮어쓰기).

### 2.7 phase 소요 시간 CSV (선택)

잡의 단계(phase)별 소요 시간을 리포트에 넣으려면, 단계 추출 스크립트가 만든 CSV 를 데이터 폴더에 함께 넣는다. 머리글을 보고 자동으로 찾는다.

- 형식: 한 행 = 잡 1개. 열 `Hostname`, `Workload`, `JobStart_KST`(예: `2026-07-15T02-05-02`), `JobIdx`, `JobTotal`, `Stage_Count`,
  단계마다 `<단계>_self`(그 단계만의 소요 초)와 `<단계>_total`(잡 시작부터 그 단계 끝까지 누적 초), `TotalElapsed_Sec`, `SrcFile`.
  단계 순서는 열 순서다. 값 `-1` 은 그 단계가 기록되지 않았다는 뜻이다.
- 케이스 연결: `JobStart_KST` 가 케이스의 잡 시작 시각 앞뒤 10분 안인 잡을 그 케이스의 잡으로 본다.
  `Hostname` 이 케이스의 VM 이름과 맞는 잡이 있으면 그 잡만 쓴다. 같은 시각에 시작한 케이스가 여럿이고 `Hostname` 이 어느 VM 이름과도 맞지 않으면 쓰지 않고 로그에 알린다.
- 계산: 단계 값은 연결된 잡들의 self 시간 평균(동시 실행 잡 평균)이다. 단계의 시작과 종료는 잡 시작 기준으로 self 시간을 차례로 더한 값이다.
  Load 는 `init_total` 평균, Compute 는 전체에서 Load 를 뺀 값이다.
- 견본: `samples\sample_data\phase\sample_phase_times.csv` (CASE-A · CASE-B, 잡 4개씩).

### 2.8 잡 TAT 원장 CSV (선택)

잡마다 시작·종료 시각과 elapsed 가 기록된 CSV(로그 수집 시스템에서 내보낸 잡 기록)를 데이터 폴더에 함께 넣으면, 머리글을 보고 자동으로 찾는다.
파일 이름은 정하지 않아도 된다.

- 필요한 열: `PSStartTime`, `PSEndTime`(예: `2026-08-11_10:00:00`), `Job_elapse`(초). 쓰는 열: `Job_code`(잡 종류), `job_info`(잡 이름, 끝에 `<i>_of_<n>`), `hostname`.
  다른 열은 쓰지 않고, 같은 잡이 두 번 기록된 행은 한 번만 센다.
- 케이스 연결: 케이스 실행 구간 앞뒤 10분 안에 시작한 잡을 그 케이스의 잡으로 본다. `hostname` 이 케이스의 VM 과 맞는 잡이 있으면 그 잡만 쓴다.
- 잡 구분은 VM 이름이 아니라 기록 내용으로 판단한다. 한 파일에 여러 종류의 잡이 섞여 있어도 되고, VM 수와도 관계없다.
  - 세트: 같은 `Job_code` · 같은 `hostname` 에서 시작 시각이 10초 안인 잡 묶음
  - TAT 측정 잡: VM(`Job_code` · `hostname`)마다, 케이스 잡 시작 시각 앞뒤 10분 안에 시작한 세트 가운데 잡 elapsed 평균이 가장 긴 세트.
    그 평균이 케이스 실행 구간의 절반 이상이어야 한다. TAT = 그 세트 잡들의 elapsed 평균. `N_of_M` 일괄형과 `1_of_1` 잡을 동시에 실행하는 개별형을 모두 처리한다.
  - VM 이 여러 대여도 된다. 예: VM 두 대에서 같은 잡을 오래 실행하고 세 번째 VM 에서 다른 잡을 여러 번 실행하면, 앞의 두 VM 은 VM 마다 TAT 측정 잡이 되고(TAT 도 VM 마다), 세 번째 VM 의 잡은 동시 실행 잡이 된다.
  - 동시 실행 잡: TAT 측정 잡이 아닌 나머지 잡. `Job_code` · `hostname` 마다 세트로 묶는다.
    기준 구간은 TAT 측정 잡의 실행 구간(첫 잡 시작 ~ 마지막 잡 종료)이고, TAT 측정 잡이 없으면 케이스 실행 구간이다.
    `기준 구간 중 시작한 세트` 는 기준 구간 시작 10초 전에 시작한 세트부터 기준 구간 끝까지 시작한 세트이고, 끝난 뒤 시작한 세트는 넣지 않는다.
- 문서와 HTML 의 잡 이름은 데이터의 `Job_code` 를 그대로 쓴다.
- 견본: `samples\sample_data\tat\sample_job_tat.csv` (CASE-A · CASE-B: TAT 측정 잡 4개와 동시 실행 잡 세트).

## 3. 실행

### 3.1 창 화면

1. `run_gui.bat` 을 실행한다.
2. `케이스 정보 파일` 의 `찾기…` 로 CSV 또는 엑셀 파일을 고른다. 데이터 폴더와 결과 폴더는 그 파일이 있는 폴더 기준으로 자동으로 채워지며, 다르면 바꾼다.
3. TC별 정리 파일이 필요하면 `TC별 정리 폴더` 를 지정한다(2.6).
4. 필요하면 `제목` 과 `기준 케이스` 를 적는다. 지표가 많으면 `VM 핵심 지표만 넣기` 를 체크한다.
   - `그래프 색 계열`: 케이스 문서 그래프의 색상 팔레트(4.4의 7가지). 기본은 1번 파랑 계열이다.
   - `그래프 폭 (cm)`: 케이스 문서 안 그래프 폭. 기본 16.5 cm 는 세로 페이지이고, 더 넓히면 가로 방향 페이지로 만든다.
     가로 Letter 페이지에 들어가지 않는 폭은 A3 가로 페이지로 만든다. 최대 31.5 cm.
     Confluence 로 가져올 문서는 31.5 를 쓴다(3.7).
   - `단위 변환 (선택)`: 체크하면 크기 단위를 GB 로, 네트워크 속도를 Gbps 로 바꾼다(3.8). 기본은 원래 단위 그대로다.
   - `TAT 비교 기준 (선택)`: TAT 비교 기준값(초)과 그 설명(예: BM 기준선). 잡 TAT 원장(2.8)이 있을 때 문서와 HTML 에 저하율을 적는다.
     비우면 저하율을 넣지 않는다. 값과 설명은 바꿀 때까지 저장된다(`%APPDATA%\perfreport\settings.json`).
   - `종료 기준 VM (선택)`: 잡 종료 시각을 비운 케이스에서 종료를 판단할 VM 이름 · 패턴(2.4). 바꿀 때까지 저장된다.
5. 지표 역할을 정하려면 `지표 역할 지정…` 을 누른다(3.2). 정하지 않으면 기본 리포트 양식으로 만든다.
   - HTML 에서 고른 항목만으로 만들려면 `HTML 선택 파일 (선택)` 에 HTML 의 `선택 내보내기` 파일을 고른다(4.3).
     그 파일의 케이스, VM, 지표만으로 Word 와 HTML 을 만든다.
6. `리포트 생성` 을 누른다. 로그 창에 읽은 파일, 케이스별 값 개수, 실행 구간, 수집 점검 결과, 지표 역할이 나온다.
7. `결과 폴더 열기` 로 결과를 연다.

### 3.2 지표 역할 지정

리포트를 만들 때마다 지표의 역할을 정할 수 있다. 문서와 HTML 은 지표를 역할 순서로 싣는다.
역할은 다섯 가지이고, 아래 표의 순서대로 나온다.

| 역할 | 뜻 |
| :-- | :-- |
| 핵심 성능 지표 | 기준 실행 대비 결과 비교에 사용하는 지표 |
| 원인 분석 지표 | 변경 설정의 영향을 직접 받는 커널 또는 PMU(Performance Monitoring Unit) 원본 카운터로, 핵심 성능 지표 차이의 원인을 자원 수준에서 설명하는 지표 |
| 세부 분석 지표 | 핵심 성능 지표 또는 원인 분석 지표가 예상과 다를 때 원인 범위를 한정하는 지표 |
| 상충 지표 | 핵심 성능 지표 또는 원인 분석 지표가 기대 방향으로 변할 때 반대 방향으로 변할 수 있는 다른 성능 지표 |
| 측정 조건 확인 항목 | 기준 실행과 비교 실행에서 같게 유지할 조건이 실제로 같았는지 확인하는 항목 |

1. `케이스 정보 파일` 과 `데이터 폴더` 를 고른 뒤 `지표 역할 지정…` 을 누른다.
   케이스에 쓰일 데이터 파일에서 지표 목록을 읽어 새 창을 연다. `VM 핵심 지표만 넣기` 를 체크했으면 그 지표만 나온다.
2. `지표 검색` 칸에 지표 이름, 분류, 역할 이름의 일부를 적으면 목록에 그 지표만 남는다.
3. 지표 줄을 누르면 체크(☑)가 바뀐다. 여러 지표를 함께 체크할 수 있다.
4. 오른쪽 역할 버튼을 누르면 체크한 지표에 그 역할이 지정된다. 지표는 그 역할의 맨 뒤 순서로 들어가고, 체크는 풀린다.
5. 같은 역할 안의 순서를 바꾸려면 지표를 체크하고 `위로` 또는 `아래로` 를 누른다. `역할 해제` 는 체크한 지표의 역할을 지운다.
6. `저장…` 으로 역할 파일을 남기고, 다음에 `불러오기…` 로 다시 쓴다.
   이번 데이터에 없는 지표는 불러올 때 빠지고, 뺀 지표 수가 창에 나온다.
7. `확인` 을 누르면 기본 창에 역할별 지정 개수가 나온다. `취소` 를 누르면 바꾼 내용을 버린다.

- 지표 하나에는 역할 하나만 지정한다.
- 역할을 지정하지 않은 지표는 기본 창의 `역할을 지정하지 않은 지표도 넣기 (문서는 Appendix A)` 로 정한다.
  켜면(기본값) 문서의 Appendix A 와 HTML 지표 목록에 넣고, 끄면 문서와 HTML 모두에서 뺀다.
- 역할을 하나도 지정하지 않으면 기본 리포트 양식(분류별 절)으로 만든다.
- 역할을 지정해 만들면 결과 폴더에 `metric_roles.csv` 가 남는다. 어떤 역할로 만들었는지 확인할 수 있고, 같은 역할로 다시 만들 때 불러온다.
- 역할 파일은 UTF-8 CSV 이고 열은 `지표, 역할, 순서` 다. 역할 칸에는 위 다섯 이름을 그대로 쓰고, 순서는 같은 역할 안의 출력 순서(1부터)다.

### 3.3 명령

```
perfreport.exe run <케이스정보.csv> <데이터폴더> [--out 결과폴더] [--title 제목] [--baseline 케이스명] [--core]
                   [--roles 역할파일.csv] [--no-unassigned] [--palette 1~7] [--chart-width cm] [--workers N]
                   [--selection HTML선택파일.json] [--to-gb] [--to-gbps] [--tat-baseline 초] [--tat-baseline-note 설명] [--end-ref-vm 이름;패턴]
perfreport.exe inspect <파일> [프로파일]      파일에서 읽히는 지표 · VM · 시각 범위 확인
perfreport.exe gui
```

- `--roles`: 역할 파일(3.2)로 지표 역할을 지정한다. 빼면 기본 리포트 양식으로 만든다.
- `--no-unassigned`: 역할을 지정하지 않은 지표를 문서와 HTML 에서 뺀다.
- `--palette`: 케이스 문서 그래프의 색 계열. 번호(1~7) 또는 이름. 기본 1 파랑 계열.
- `--chart-width`: 케이스 문서 안 그래프 폭(cm). 기본 16.5, 최대 31.5. 16.5 를 넘으면 가로 방향 페이지로 만든다.
  Confluence 로 가져올 문서는 31.5 를 쓴다(3.7).
- `--to-gb` · `--to-gbps`: 크기 단위를 GB 로, 네트워크 속도를 Gbps 로 바꾼다(3.8).
- `--tat-baseline 초` · `--tat-baseline-note 설명`: TAT 비교 기준값과 설명. 주면 저하율 = (TAT − 기준) ÷ 기준 × 100 을 적는다.
- `--end-ref-vm 이름;패턴`: 잡 종료 시각을 비운 케이스에서 종료를 판단할 VM(2.4).
- `--selection`: HTML 의 `선택 내보내기` 파일. 그 케이스, VM, 지표만으로 만든다.
- `--workers`: 그래프를 나눠 그릴 프로세스 수. 기본은 CPU 수 - 1 (최대 6). 1 이면 순서대로 그린다.
  환경 변수 `PERFREPORT_WORKERS` 로도 정한다.

| Appendix (잡 결과 표) | 잡 TAT 원장 · phase 소요 시간 CSV 가 있을 때만. TAT 측정 잡별 elapsed 표, phase 별 소요 시간 표, 동시 실행 잡의 잡 요약 · 가동 구간 · 세트별 · 잡별 표. 있으면 데이터 출처 앞에 오고 뒤 Appendix 글자가 하나씩 밀린다 |
| Appendix A | 데이터 출처: 분류별 수집 시스템과 시간대 |
| Appendix B | 지표별 표본 수: 행은 지표, 열은 VM, 값은 실행 구간 안 표본 수. 같은 지표에서 VM 끼리 수가 다르면 수집이 빠졌거나 수집 간격이 다르다 |
| Appendix C | 데이터 가용성: VM·수집 시스템별 실행 구간 안 표본 시각 수와 최대 공백 |

케이스 문서 구성 (지표 역할을 지정했을 때):

| 절 | 내용 |
| :-- | :-- |
| 1. 케이스 식별 | 기본 양식의 항목에 `지표 역할` 행을 더한다. 역할별 지정 개수와 역할 미지정 지표 수, 그 지표의 수록 여부를 적는다 |
| 2. 요약 | VM별 핵심 성능 지표. 지표마다 평균 칸과 최대 칸(남은 자원 지표는 평균과 최소). 열 순서는 지정 순서다. 핵심 성능 지표를 지정하지 않았으면 기본 양식의 요약 표 |
| 3~. 역할별 절 | 지정한 역할만 역할 순서대로 절 하나씩. 지표마다 그래프 1장과 한 줄 설명(분류, 단위, 수집 시스템), 절 끝에 통계 표 |
| Appendix A | 역할 미지정 지표: 분류별 그래프와 통계 표. `역할을 지정하지 않은 지표도 넣기` 를 켰을 때만 |
| Appendix B | 데이터 출처 |
| Appendix C | 지표별 표본 수 |
| Appendix D | 데이터 가용성 |

`역할을 지정하지 않은 지표도 넣기` 를 끄면 역할 미지정 지표 절이 빠지고, 데이터 출처부터 Appendix A 로 한 글자씩 당겨진다.

- 값이 없는 칸은 빈 칸으로 둔다. 값이 0 이면 0 을 적는다.

- 수집 지표는 시점·시험마다 달라도 된다. 데이터에 있는 지표만 싣고, 지표 분류는 이름으로 정한다(`CPU|Usage (%)` 처럼 `|` 앞이 분류, 그 밖은 낱말 규칙).
- 그래프 안에는 축·범례·데이터만 둔다. 축 라벨은 영문(`Elapsed time (s)`)이고 제목·설명은 본문에 쓴다.
- 해석 문장은 넣지 않는다. 표와 그래프에 실측값만 싣는다.

### 3.6 생성 속도와 DRM 환경

- 케이스 문서의 그래프는 여러 프로세스가 나눠 그린다(기본: CPU 수 - 1, 최대 6). 순서대로 그린 결과와 같다.
- 병렬 처리를 쓰지 못하면 남은 그래프를 순서대로 그리고, 로그에 `[속도] 병렬 처리를 멈추고 …` 를 남긴다.
  - 프로세스를 만들지 못한 경우, 3분 안에 답이 없는 경우, 도중에 프로세스가 끝난 경우가 해당한다.
  - 보안 프로그램이 프로세스 생성을 막는 PC 가 이런 경우다.
- Windows 실행 파일에서 병렬 처리가 바르게 동작하도록 PyInstaller 문서의 권장 방법을 따른다.
  - 실행 파일 진입점에서 `multiprocessing.freeze_support()` 를 다른 무거운 부품을 불러오기 전에 부른다.
  - 콘솔 없는 실행 파일이면 표준 출력을 빈 출력으로 바꾼다. 병렬 처리용 프로세스는 우선순위를 낮춰 창 화면이 멈추지 않게 한다.
- `build_windows.bat` 의 마지막 단계(6/6)는 견본으로 프로세스 2개를 써서 리포트를 만들어 본다.
  - 병렬 처리가 안 되는 PC 면 안내를 보이고, 순서대로 그리는 방식으로 다시 시험한다.
- 병렬 처리를 끄려면 `--workers 1` 을 주거나 환경 변수 `PERFREPORT_WORKERS=1` 을 정한다.
- 문서 서식은 프로그램 안에 들어 있어, 설치 폴더의 Word 서식 파일을 읽지 않는다. DRM 이 Word 파일을 암호화하는 PC 에서도 문서를 만든다.
- 만든 문서를 다시 열지 않는다. 문서를 저장한 뒤 DRM 이 암호화해도 생성은 끝까지 진행된다.
- 같은 이름의 문서가 열려 있거나 보호되어 덮어쓸 수 없으면 새 이름으로 저장한다(3.5).
- 케이스 정보는 DRM 이 걸리지 않는 CSV 로 쓰는 것을 권한다. 엑셀(.xlsx)이 암호화되어 있으면 CSV 로 저장하라는 안내가 나온다.

### 3.7 Confluence 로 가져오기

Confluence(Data Center)의 `Word 문서 가져오기` 를 쓸 때의 제약과 이 프로그램의 대응이다.

- 가져오기는 문서를 위키 마크업으로 바꾸면서 위키 마크업 기호를 그대로 둔다(Atlassian 버그 CONFSERVER-53030).
  표 칸의 `|` 는 새 열로 나뉘고, `[ ]` 는 깨진 매크로가 된다.
  - Word 문서의 글자에서 `|` 는 ` > ` 로 바꾼다. 예: `CPU|Usage (%)` → `CPU > Usage (%)`. HTML 은 원래 이름 그대로다.
  - `[ ]` · `{ }` 는 `( )` 로, 역슬래시는 `/` 로 바꾼다.
  - 값이 없는 칸은 `-` 대신 빈 칸으로 둔다.
  - 표에 병합 칸을 쓰지 않는다. 요약 표의 지표 이름은 평균 칸 위에만 적고 최대 칸 위는 비운다.
- 가져오기는 그림을 Word 에 보이는 크기로 줄여 싣는다. 기본 한도는 Word 에 보이는 크기 1200 x 900 px 이고, 넘으면 가져오기가 거부된다(Office Connector 설정).
  - 그래프 폭 16.5 cm 는 Confluence 에서 약 620 px 이다. Confluence 로 가져올 문서는 그래프 폭을 31.5 cm(약 1190 x 640 px)로 만든다.
  - 그래프 폭을 넓혀도 그림 파일의 크기는 같다.
- 가져오기는 압축을 푼 크기 20 MB 를 넘는 문서를 받지 않는다(관리자가 바꿀 수 있다).

### 3.8 단위 변환과 계산 지표

- `크기를 GB 로`(`--to-gb`): 이름 끝 괄호 단위(`(KB)` 등)나 이름 끝 `_MB` 같은 표기를 읽어 GB 로 바꾼다. 바이트 단위는 1024 배수다(1 GB = 1024 MB).
- `네트워크 속도를 Gbps 로`(`--to-gbps`): Network 분류 지표의 속도 단위(`(KBps)`, `_Mbps` 등)를 Gbps 로 바꾼다.
  비트 단위는 1000 배수(1 Gbps = 1000 Mbps)이고, 바이트 단위 속도는 1 KBps = 1024 x 8 bit/s 로 환산한다. 디스크 처리량은 바꾸지 않는다.
- 이름 안의 단위 표기도 같이 바꾼다. 예: `AnonHugePages_MB` → `AnonHugePages_GB`, `Memory|Consumed (KB)` → `Memory|Consumed (GB)`.
- 역할 파일, HTML 선택 파일, 분석 프로파일의 지표 이름은 단위 표기만 다르면 같은 지표로 본다. 단위 변환을 켜고 끄며 같은 역할 파일을 쓸 수 있다.
- `THP Coverage (%)`: 데이터에 `AnonHugePages` 와 `AnonPages`(예: `AnonHugePages_MB`, `AnonPages_MB`)가 있으면 같은 시각 값으로 `AnonHugePages ÷ AnonPages × 100` 을 계산해 지표를 만든다.
  그래프, 요약 표, 통계 표에 들어간다. THP coverage 지표가 이미 있는 VM 은 만들지 않고, AnonPages 가 0 인 시각은 비운다.

## 4. HTML 뷰어

### 4.1 한 그래프에 비교 (기본)

1. **케이스 선택**: 케이스를 체크하면 그 케이스의 VM이 선으로 모두 추가된다. 케이스마다 호스트가 달라도 된다.
   - 선은 한 그래프에 최대 8개다. 넘으면 들어가는 만큼만 추가하고, 추가하지 못한 VM 수를 안내 문구로 보인다.
   - 체크한 케이스 아래의 `색 계열` 칸에서 그 케이스 선들의 색 계열(팔레트)을 바꾼다(4.4).
2. **지표 선택**: 목록에서 지표를 체크한다. 한 번에 최대 6개까지 고르고, 지표마다 그래프가 하나씩 그려진다.
   - `지표 검색` 칸에 이름의 일부를 적으면 목록에 그 지표만 남는다. `지표 선택 해제` 는 고른 지표를 모두 푼다.
   - 지표 역할을 지정해 만든 HTML 은 목록이 역할 순서로 묶여 있고, 처음 화면에 핵심 성능 지표가 지정 순서대로 최대 6개 선택되어 있다.
3. 고른 케이스의 VM이 지표마다 한 그래프에 겹쳐 그려진다. 선 하나는 케이스 + VM 하나이고, 모두 실선이며 색으로 구별한다(한 그래프에 최대 8개).
   가로축은 각 케이스의 잡 시작 시각을 0초로 둔 경과 시간이라, 실행 시각이 달라도 같은 위치에서 비교된다.
4. **VM 선택**: VM 목록은 케이스별로 나뉜다.
   - VM 이름을 누르면 **그 케이스에서는** 그 VM만 남는다. 다른 케이스의 선택은 그대로다.
     예: CASE-A에서 `esx01-vm01` 을, CASE-C에서 `app-a` 를 누르면 두 VM을 한 그래프에서 비교한다. 이름 규칙이 달라도 된다.
   - 체크박스로 여러 VM을 함께 고른다. `전체 선택` 으로 되돌린다.
   - 색 상자로 그 선 하나의 색을 바꾼다.
5. **통계표**: 고른 지표별로 묶어 보인다. 지표마다 표의 첫 번째 선을 기준으로 나머지 선의 평균 차이를 보인다.
   첫 번째 선은 케이스 순서대로, 같은 케이스 안에서는 VM 순서대로 정한다.

### 4.2 케이스별 그래프

`보기` 에서 `케이스별 그래프` 를 고르면 지표마다, 케이스마다 그래프를 하나씩 그리고 가로축을 연동한다.
고른 VM이 없는 케이스는 `선택한 VM 이 없는 케이스` 로 표시한다.

### 4.3 공통 기능

- **가로축**: 경과 시간(s)과 실제 시각 중에서 고른다.
- **평균 구간**: 원 데이터, 1분, 5분, 10분 평균 중에서 고른다. `자동 평균` 은 선 하나의 점이 600개를 넘을 때만 구간 평균으로 그린다. 통계표는 항상 원 데이터 기준이다.
- **그래프 크기**: 도구 줄의 `그래프 크기` 칸에서 높이(작게, 보통, 크게, 아주 크게)와 폭(화면 폭의 100%, 80%, 60%)을 고른다. 고른 크기는 브라우저에 저장된다.
- **선택 내보내기**: 지금 고른 케이스, VM(선), 지표를 `perfreport_selection.json` 파일로 저장한다.
  리포트 생성기의 `HTML 선택 파일` 칸(명령은 `--selection`)에 넣으면 그 항목만으로 Word 리포트를 만든다.
- **확대·이동**: 그래프 위를 드래그하면 그 영역이 확대된다. `이동` 을 고르면 드래그로 화면을 옮긴다. 마우스 휠로도 확대·축소하고, 더블클릭하거나 `전체 보기` 를 누르면 원래 범위로 돌아간다.
- **스크롤바**: 그래프 아래 막대는 가로 범위, 오른쪽 막대는 세로 범위를 조정한다. 막대 가운데를 끌면 이동하고, 막대 양 끝을 끌면 범위가 넓어지거나 좁아진다.
- **연동**: 한 그래프에서 가로 범위를 바꾸면 모든 그래프가 같은 범위로 맞춰진다. 세로축은 그래프마다 보이는 구간의 데이터에 맞추고, `세로축 범위도 연동` 을 켜면 같은 지표의 그래프끼리 같은 세로 범위를 쓴다.
- **선 색 변경**: 케이스 목록의 `색 계열` 칸으로 케이스의 팔레트를, VM 목록의 색 상자로 선 하나의 색을 바꾼다.
  - 바꾼 설정은 브라우저에 저장되어 같은 PC·같은 브라우저의 다른 리포트에도 적용된다.
  - `색 설정 내보내기` · `색 설정 가져오기` 로 다른 PC에 옮기고, `색 초기화` 로 바꾼 설정을 모두 지운다.
- **통계표**: 선택한 케이스·VM의 평균, p95, 최댓값과, 같은 지표 첫 번째 선 대비 평균 차이.
- **화면 모드**: 오른쪽 위 버튼으로 밝은 화면과 어두운 화면을 바꾼다.

### 4.4 색 규칙

| 구분 | 표현 | 규칙 |
| :-- | :-- | :-- |
| 케이스 | 색 계열(팔레트) | 케이스를 체크한 순서대로 아직 쓰지 않은 팔레트를 받는다. 체크를 풀면 반납한다 |
| VM | 선 색 | 그 케이스 팔레트의 색을 VM 순서(호스트, VM 이름 순)대로 받는다. 같은 VM이라도 케이스가 다르면 색 계열이 다르다 |
| 선 모양 | 실선 | 모든 선이 실선이다 |
| 바꾼 색 | 색 계열 칸, 색 상자 | 케이스 목록의 `색 계열` 칸과 VM 목록의 색 상자로 바꾼 설정이 자동 배정보다 우선한다 |

팔레트는 7가지다: 1 파랑 계열, 2 주황·빨강 계열, 3 파랑·주황 교차, 4 초록 계열, 5 보라·분홍 계열, 6 갈색·노랑 계열, 7 회색 계열.
- 3번 파랑·주황 교차는 1번과 2번의 색을 번갈아 놓은 팔레트다. 한 케이스 안에서 이웃한 VM 이 파랑과 주황으로 갈린다.
- 3번은 1·2번과 같은 색을 쓰므로 HTML 의 자동 배정에서는 빠지고, `색 계열` 칸에서 고를 때만 쓰인다.
- 케이스 문서는 리포트 생성기에서 고른 팔레트 하나를 쓴다(기본 1번 파랑 계열).
팔레트마다 8색이 있고, 이웃한 VM끼리 구별되도록 진하기를 번갈아 놓았다. 어두운 화면에서는 같은 색을 밝게 그린다.
자동 배정 팔레트(6가지)보다 케이스가 많아 같은 팔레트를 다시 쓰면 그 팔레트의 5번째 색부터 쓴다.

## 5. 외부 통신

| 구성 요소 | 외부 통신 | 근거 |
| :-- | :-- | :-- |
| perfreport | 없음 | 데이터 파일과 케이스 정보 CSV를 읽고 결과 폴더에 쓰기만 한다. 네트워크 기능이 없다 |
| HTML 뷰어 | 없음 | 그래프 라이브러리와 데이터가 파일 안에 들어 있다. 선 색 설정은 그 PC 브라우저 저장소에만 저장된다 |

외부 통신이 필요한 시점은 인터넷이 되는 PC에서 실행 파일을 빌드할 때 한 번뿐이다(Python 부품 내려받기).

## 6. 새 데이터 형식 추가

코드는 고치지 않는다. `profiles\inputs\` 에 프로파일(YAML) 하나를 추가하면 데이터 폴더에서 그 형식의 파일을 자동으로 읽는다.

1. 비슷한 프로파일을 복사해 열 이름을 고친다.
   - `csv_wide`: 한 행이 한 시각이고 지표가 열인 CSV. `time_column`, `entity_column`(VM 이름), `host_column`(선택), `time_format`(선택)
   - `kv_text`: `Key:Value, Key:Value` 형식 텍스트. `time_key`, `entity_key`, `units`(선택)
2. `perfreport.exe inspect <파일> <프로파일 이름>` 으로 읽히는 지표, VM, 시각 범위를 확인한다.
3. 리포트에 넣을 지표를 고르려면 `profiles\analysis\` 에 분석 프로파일을 추가한다(`vm_core.yaml` 참고).

### 4.5 잡 결과 그래프 (phase 소요 시간 CSV · 잡 TAT 원장이 있을 때)

도구 막대 아래 `잡 결과 그래프` 줄에서 지표 목록과 따로 고른다. 체크한 케이스 가운데 데이터가 있는 케이스만 나온다.

| 항목 | 기본 | 내용 |
| :-- | :-- | :-- |
| phase 누적 막대 | 켬 | 아래 설명 |
| TAT | 끔 | 케이스 · VM 마다 TAT 측정 잡의 잡 elapsed 평균 막대. TAT 비교 기준값이 있으면 점선과 저하율. 아래에 TAT 측정 잡 표(잡마다의 elapsed, TAT, 최대 − 최소, 저하율) |
| 동시 실행 잡 평균 elapsed | 끔 | 케이스 · 잡 종류마다 막대. 막대 위에 기준 구간 중 시작한 세트 수 |
| 동시 실행 잡 세트별 elapsed | 끔 | 케이스 · 잡 종류마다 그래프 1개. 점 = 잡, 선 = 세트 평균, 세트마다 평균을 숫자로 적는다(잡마다의 값은 아래 표와 점에 마우스를 올리면). 가로축은 기준 구간 시작부터 세트 시작까지의 시간. `phase 배경 밴드` 를 체크하면 배경에 phase 구간. 아래에 세트별 표(잡마다의 elapsed, 평균 · 최소 · 최대, 기준 구간 안 · 밖) |


- 지표 그래프 위에 `phase 별 self 시간 누적` 그래프가 나온다. 체크한 케이스 가운데 phase 가 있는 케이스마다 막대 1개이고, 아래부터 실행 순서로 단계를 쌓는다.
  막대 높이의 5% 이상인 단계는 막대 안에 값을, 막대 위에는 `Total` 을 적는다. 막대에 마우스를 올리면 단계별 값이 나온다.
- 도구 막대의 `phase 배경 밴드` 를 체크하면 시계열 그래프 배경에 phase 구간을 그린다(기본은 끔).
  `케이스별 그래프` 에서는 케이스마다 그리고, `한 그래프에 비교` 에서는 phase 가 있는 케이스가 하나일 때만 그린다(케이스마다 phase 구간이 달라서).

## 7. Windows 설치

인터넷이 되는 Windows PC에서 한 번 빌드하고, 결과 폴더를 사용할 PC로 옮긴다. 사용할 PC에는 Python과 인터넷이 필요 없다.

1. Python 3.12를 설치한다(python.org, 설치 첫 화면에서 "Add python.exe to PATH" 선택).
2. 이 패키지를 영문 경로에 풀고(예: `C:\perfreport-src\`) `build_windows.bat` 을 실행한다.
   - 진행 단계가 [1/6]~[6/6]로 표시된다. 부품 설치 뒤 불러오기 점검, 만든 실행 파일의 시험 실행, 견본 리포트 생성 시험(병렬 처리 포함)까지 한다.
   - 마지막에 `Done: dist\perfreport\perfreport.exe` 가 나오면 성공이다.
3. 생성된 `dist\perfreport\` 폴더를 사용할 PC로 옮긴다(예: `C:\perfreport\`).
4. 옮긴 폴더의 `run_gui.bat` 을 실행한다.

`No module named pandas` 가 나오면 빌드 전의 소스 폴더에서 실행한 경우다. `build_windows.bat` 을 먼저 실행하고, 끝난 뒤 `dist\perfreport\run_gui.bat` 을 실행한다.

패키지 설치 단계에서 내려받기가 실패하면, 빌드 스크립트가 pypi.org 와 files.pythonhosted.org 의 인증서 확인을 생략하는 옵션(`--trusted-host`)으로 한 번 더 시도한다.
회사망 보안 장비가 HTTPS 를 검사하면 pip 가 인증서를 확인하지 못해 이렇게 실패한다. 이 옵션은 그 실행에만 적용되고 PC 설정에 남지 않는다.
그래도 `FAILED while installing packages` 가 나오면 인터넷 연결이나 회사망 프록시를 확인한다.
회사에 Python 패키지 저장소가 있으면 `py -3 -m pip config --user set global.index-url https://<저장소 주소>/simple` 로 한 번 지정한 뒤 빌드한다.

빌드 없이 Python으로 바로 실행하려면 이 폴더에서 다음을 실행한다.
```
py -3 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m perfreport gui
```

견본 데이터를 다시 만들려면 `python samples\make_sample_data.py` 를 실행한다.
