# 테스트 실행 명령 생성기 (tcgen)

테스트 케이스 표를 입력하면, 점프 VM 터미널과 ESX root SSH 창에 붙여넣을 crontab 등록 블록을 만든다.
사용자는 명령과 케이스를 화면에 입력하고 [명령어 생성] 을 누른 뒤, 만들어진 블록을 복사해 붙여넣는다.

## 1. 구성

| 파일 | 내용 |
| :-- | :-- |
| `tcgen_app.py` | 화면 |
| `tcgen_core.py` | 시각 계산, crontab 줄, 붙여넣기 블록, 기록 파일 저장 |
| `run_gui.bat` | 실행. `tcgen.exe` 가 있으면 그것을, 없으면 설치된 Python 으로 실행한다 |
| `build_windows.bat` | Windows 실행 파일(`dist\tcgen\tcgen.exe`) 빌드 |
| `tests\` | 자동 시험(`test_core.py`, `test_blocks_shell.py`)과 화면 점검(`gui_smoke.py`) |

Python 표준 라이브러리만 쓴다. 추가 패키지는 필요 없다.

## 2. 설치와 실행

- Python 3.9 이상이 있는 PC: `run_gui.bat` 을 실행한다. `python tcgen_app.py` 와 같다.
- Python 이 없는 PC: Python 과 인터넷이 있는 PC 에서 `build_windows.bat` 을 실행한다. 만들어진 `dist\tcgen` 폴더를 통째로 복사해 `tcgen.exe` 를 실행한다.

설정, 명령 목록, 테스트 케이스 표는 생성기 폴더(`tcgen.exe` 또는 `tcgen_app.py` 가 있는 폴더)가 아니라 데이터 폴더에 저장한다. 데이터 폴더 기본 위치는 `C:\Users\<계정>\tcgen_data` 이다. 생성기를 다시 빌드하거나 다른 폴더로 옮겨도 데이터 폴더는 그대로 남는다. 네 파일 모두 바뀔 때마다 자동 저장되고, 생성기를 다시 열면 불러온다. 저장 버튼은 없다.

| 파일 (데이터 폴더 기준) | 내용 |
| :-- | :-- |
| `settings.json` | 테스트 기록 CSV 경로, 로그 폴더, VM 접속 계정, 모니터링 시작 분, 중지 분 |
| `run_commands.csv` | 탭 1 실행 명령 목록 |
| `monitor_commands.csv` | 탭 2 모니터링 명령 목록 |
| `test_cases.json` | 탭 3 테스트 케이스 표와 적용 체크 상태. 표가 바뀔 때마다 저장 |
| `testcases\test_record.csv` | 테스트 기록 CSV 기본 위치 |
| `testcases\testcaselogging-년월일시분초.csv` | 생성할 때마다 만드는 로그 (기본 위치) |
| `backup\년월일시분초_before_restore\` | [백업 불러오기] 직전의 데이터 파일 |

| 설정 파일 | 내용 |
| :-- | :-- |
| `C:\Users\<계정>\AppData\Roaming\tcgen\config.json` | [데이터 폴더 변경] 으로 바꾼 데이터 폴더 위치, 마지막으로 고른 백업 위치. 이 파일이 없으면 기본 위치를 쓴다 |

- 명령 목록은 화면에서만 고친다. 엑셀로 열어 저장하면 DRM 이 파일을 암호화해 생성기가 읽지 못할 수 있다.
- 테스트 기록 CSV 나 로그 폴더를 데이터 폴더 밖으로 지정했다면 그 파일은 [설정 백업] 에 들어가지 않는다.
- `build_windows.bat` 을 다시 실행하면 PyInstaller 가 `dist\tcgen` 폴더를 통째로 지우고 새로 만든다. 데이터는 데이터 폴더에 있어 지워지지 않는다.
- 예전 판은 데이터를 생성기 폴더에 저장했다. 새 판을 처음 실행할 때 데이터 폴더가 비어 있고 생성기 폴더에 예전 파일이 있으면, 데이터 폴더로 복사한 뒤 생성기 폴더의 원본을 `moved_to_data_folder_<시각>` 폴더로 옮긴다. `build_windows.bat` 은 `dist\tcgen` 에 예전 판 데이터 파일이 있으면 빌드 전에 `build_olddata` 에 보관했다가 빌드 뒤 다시 넣는다. 그래서 다시 빌드한 새 판도 처음 실행할 때 예전 데이터를 옮겨 온다.
- `settings.json` 의 `vm_prefix` (기본 `ev`) 와 `default_vms` (기본 2) 는 VM 이름 자동 입력에 쓴다. VM 이름 = ESX 호스트 + `vm_prefix` + 두 자리 번호 (예: `esx01ev01`), 새 케이스의 VM 수 = `default_vms`. 화면에는 없고 이 파일에서만 바꾼다.
- 예전 판의 테스트 케이스 표(PVM, SVM 칸)는 처음 열 때 VM 2대짜리 케이스로 바꾼다. 바꾸기 전 원본은 데이터 폴더 `backup\<시각>_before_vm_format\` 에 복사한다.

## 3. 화면

### 3.1 설정 줄

| 항목 | 내용 |
| :-- | :-- |
| 테스트 기록 CSV [찾기] | 기존 파일을 고르거나 새 파일 이름을 적는다. 생성할 때마다 케이스 하나에 한 행을 추가한다 |
| 로그 폴더 [찾기] | 생성할 때마다 `testcaselogging-년월일시분초.csv` 를 만든다. crontab 줄 하나에 한 행 |
| VM 접속 계정 | 점프 VM 에서 ssh 로 접속할 계정. 비우면 점프 VM 의 현재 계정으로 접속한다 |
| 모니터링 시작 N분 전 | 기본 5. 모니터링 시작 = 잡 시작 N분 전 |
| 모니터링 중지 N분 전 | 기본 10. 자동 중지 = 다음 케이스 잡 시작 N분 전 |
| [설정 백업] | 백업을 저장할 폴더를 고르면 그 안에 `tcgen_backup_년월일시분초` 폴더를 만들고 데이터 파일 4개와 `testcases` 폴더를 복사한다. 고른 위치는 다음 백업 때 처음 위치로 쓴다. 다른 드라이브나 공유 폴더를 고르면 PC 를 바꿔도 복원할 수 있다 |
| [백업 불러오기] | 백업 폴더(`tcgen_backup_...` 또는 예전 생성기 폴더)를 고르면 그 데이터 파일로 현재 데이터를 바꾸고 화면을 다시 채운다. 바꾸기 전 현재 파일은 데이터 폴더 `backup` 아래에 복사해 둔다. `testcases` 안 파일은 같은 이름이 없을 때만 복사해 테스트 기록을 덮어쓰지 않는다 |
| [데이터 폴더 열기] | 데이터 폴더를 연다 |
| [데이터 폴더 변경] | 새 폴더를 고르면 지금 데이터를 복사하고 그 폴더를 데이터 폴더로 쓴다. 고른 폴더에 이미 데이터가 있으면 그 데이터를 불러온다. 위치는 `config.json` 에 저장되어 다음 실행에도 쓴다. 생성기 폴더 안은 고를 수 없다 |
| [테스트 케이스 폴더 열기] | 로그 폴더(`testcaselogging-*.csv`)를 연다 |

### 3.2 탭 1. 실행 명령

| 열 | 내용 |
| :-- | :-- |
| App명 | 응용 이름 |
| 명령어 명 | 탭 3 에서 고르는 이름. 영문, 숫자, `.` `_` `-` 만 사용, 중복 불가 |
| 잡 조건 설명 | 예: 1 job, 4 jobs 동시. 로그 CSV 의 '설명' 열에 함께 기록한다 |
| 경로/실행 명령 | 절대 경로로 입력한다. 이 명령이 crontab 에 한 줄로 그대로 들어간다 |

명령 안에 쓸 수 있는 변수는 두 가지다.

| 변수 | 값 |
| :-- | :-- |
| `<vm이름>` | 명령이 실행되는 VM 의 hostname (`hostname -s`). ESX 명령에서는 ESX 호스트 이름 |
| `<실행시각>` | 명령이 실행된 시각 14자리, KST. 예: `20261109000000` |

예: `/home/tester/bench/run_a.sh >> /home/tester/log/run_a-<vm이름>-<실행시각>.log 2>&1`

### 3.3 탭 2. 모니터링 명령

탭 1 의 열에 실행 위치(VM 또는 ESX), 시작 명령, 중지 명령이 더해진다. 어떤 모니터링 명령이든 직접 등록한다.

- 실행 위치가 VM 인 명령은 탭 3 의 VM 행에서, ESX 인 명령은 케이스 행에서 고른다. 고른 VM 이나 ESX 호스트의 crontab 에 등록한다.
- 중지 명령을 비우면 중지 줄을 만들지 않는다.

### 3.4 탭 3. 테스트 케이스

케이스 행(굵은 글씨) 아래에 그 케이스의 VM 행(`└`)이 달린다. VM 은 몇 대든 둘 수 있다.

| 열 | 케이스 행 | VM 행 |
| :-- | :-- | :-- |
| 적용 | 체크하면 [명령어 생성] 에서 빠진다. 이미 등록한 케이스에 체크한다. 칸을 누르거나 행을 고르고 Space 를 누르면 바뀐다. 체크한 케이스와 그 VM 행은 회색으로 보인다 | 없음 |
| 케이스 / VM | 케이스 이름. 영문, 숫자, `.` `_` `-` 만 사용. 적용 체크한 행을 포함해 중복 불가 | VM 이름. 같은 케이스 안에서 중복 불가 |
| ESX 호스트 | 입력하면 VM 이름이 ESX 호스트+`ev01`, `ev02` … 로 자동 입력된다. 호스트를 바꾸면 자동으로 붙은 이름도 따라 바뀌고, 직접 고친 이름은 그대로 둔다 | 없음 |
| 잡 | 없음 | 탭 1 의 명령어 명 중에서 고른다. `(없음)` 이면 그 VM 에는 잡 줄을 만들지 않는다 |
| 모니터링 | ESX 모니터링. 칸을 두 번 누르면 실행 위치가 ESX 인 명령만 나오는 선택 창이 열린다 | 그 VM 의 모니터링. 칸을 두 번 누르면 실행 위치가 VM 인 명령만 나오는 선택 창이 열린다. VM 마다 다르게 고를 수 있다 |
| 간격 | 윗줄 잡 시작부터 이 케이스 잡 시작까지의 시간. `12:00` 형식 | 없음 |
| 잡 시작 (KST) | `2026-11-09 10:00:00` 형식. 분 단위. 그 케이스의 모든 VM 잡이 이 시각에 시작한다 | 없음 |
| 모니터링 시작 | 잡 시작 5분 전 (자동 계산) | 없음 |
| 모니터링 중지 | 칸을 두 번 누르면 자동 / 직접 입력 / 중지 없음 중에서 고른다. 자동은 다음 케이스 잡 시작 10분 전이고, 마지막 케이스는 잡 시작 + 간격 - 10분 | 없음 |

- 새 케이스에는 VM 2대(ESX 호스트+`ev01`, `ev02`)가 기본으로 들어간다.
- [+ VM 추가]: 선택한 케이스(케이스 행이나 그 아래 VM 행)에 다음 번호 VM(`ev03`, `ev04` …)을 추가한다.
- 잡과 모니터링이 모두 없는 VM 은 등록하지 않는다. 잡이 `(없음)` 이고 모니터링이 있으면 모니터링만 등록한다.
- 모니터링 시작과 중지 시각은 케이스 기준이며, 그 케이스의 모든 VM 과 ESX 에 같이 적용된다.
- [+ 케이스 추가]: 선택한 케이스를 VM 구성까지 복사해 아래에 넣는다. 간격은 그 케이스 간격을 가져오고 잡 시작 = 윗줄 잡 시작 + 간격 으로 계산한다. 이름 끝에 `-r2`, `-r3` 을 추가해 중복을 피한다. 새 케이스는 적용 체크가 꺼져 있다.
- [삭제], [위로], [아래로]: 고른 행이 케이스 행이면 케이스를, VM 행이면 그 VM 을 삭제하거나 옮긴다. 케이스를 옮길 때는 순서만 바뀌고 잡 시작, 간격, 모니터링 중지 설정은 그 행에 남는다. 케이스를 삭제해도 다른 케이스의 잡 시작은 바뀌지 않는다.
- 잡 시작이나 간격을 고치면 아래 케이스의 잡 시작이 다시 계산된다.
- 탭 3 의 표와 적용 체크 상태는 바뀔 때마다 `test_cases.json` 에 저장되고, 생성기를 다시 열면 불러온다.
- 적용 체크한 케이스도 표에 남아 시각 계산에 쓰인다. 바로 윗줄 케이스의 자동 모니터링 중지 시각은 체크한 케이스의 잡 시작 기준이다.
- 적용 체크한 케이스와 같은 이름으로는 생성할 수 없다. 같은 이름으로 생성하면 먼저 등록한 케이스의 crontab 줄이 지워지고 바뀌기 때문이다.

### 3.5 탭 4. 생성 결과

[명령어 생성] 을 누르면 입력을 검사하고, 오류가 없으면 기록 파일을 저장한 뒤 블록 세 개를 보여 준다. 오류가 있으면 블록과 기록을 만들지 않는다.

| 블록 | 붙여넣는 곳 | 하는 일 |
| :-- | :-- | :-- |
| A. 점프 VM 최초 1회 설정 | 점프 VM 터미널 (처음 한 번) | 자동 로그인용 `~/.tcgen/vmssh`, `~/.tcgen/askpass` 와 비밀번호 입력용 `~/.tcgen/setpw` 를 만들고, VM 비밀번호를 입력받아 `~/.tcgen/vmpw` 에 저장(권한 600) |
| B. VM 등록 블록 | 점프 VM 터미널 (생성할 때마다) | 잡이나 모니터링이 있는 VM 마다 ssh 로 접속해 crontab 에 줄을 등록하고, 등록된 줄을 출력한다. VM 이 몇 대든 한 번 붙여넣으면 된다 |
| C. ESX 블록 | 그 ESX 의 root SSH 창 | `/var/spool/cron/crontabs/root` 에 줄을 추가하고 `cron.update` 로 crond 에 알린다 (Broadcom KB 323138 절차) |

ESX 가 여러 대이면 C 블록의 호스트 목록에서 하나씩 골라 복사한다.

### 3.6 기록 파일

| 파일 | 행 | 열 |
| :-- | :-- | :-- |
| 테스트 기록 CSV | 케이스 하나에 한 행 | 테스트 케이스 이름, 생성 시각, ESX 호스트, VM 구성 (예: `esx01ev01=job_a, esx01ev02=job_b4`), 잡 시작(KST), 간격, 모니터링 (예: `esx01ev01:guest_perf, esx01ev03:guest_perf+guest_gpu, esx01:host_pmu`), 모니터링 시작(KST), 모니터링 중지(KST) |
| 로그 CSV (`testcaselogging-년월일시분초.csv`) | crontab 줄 하나에 한 행 | 테스트 케이스 이름, 생성 시각, 구분, 대상 (VM 이름 또는 ESX 호스트 이름), 실행 위치 (VM, ESX), 명령어 명, App명, 설명 (잡 조건 설명 또는 모니터링 설명), 실행 시각(KST), crontab 시각 기준, 명령, crontab 줄, 케이스 정보 |

- 기존 테스트 기록 CSV 의 머리글에 없는 열은 머리글 끝에 덧붙이고 이어서 기록한다. 기존 행의 새 칸은 비운다. 덧붙이기 전 원본은 데이터 폴더 `backup` 에 `<시각>_before_header_change_<파일 이름>` 으로 복사한다.
- 첫 열에는 항상 테스트 케이스 이름을 넣는다. 잡 명령은 로그 CSV 의 '명령' 열에 남는다.

## 4. 사용 순서

1. 탭 1, 탭 2 에 명령을 등록한다. 고칠 때마다 저장되고 다음 실행 때 다시 불러온다.
2. 탭 3 에 케이스를 입력한다. 케이스 행에 이름, ESX 호스트, 간격, 잡 시작을 넣고, VM 행마다 잡과 모니터링을 고른다. VM 이 더 필요하면 [+ VM 추가] 를 누른다. [명령어 생성] 을 누른다. 이미 등록한 케이스는 적용 칸을 체크해 두면 생성에서 빠진다.
3. 점프 VM 에서 처음 한 번만 A 블록을 붙여넣는다. 약 1초 뒤 `VM password:` 가 나오면 VM 비밀번호를 입력한다. A 블록은 다른 블록과 함께 붙여넣지 않는다. 붙여넣은 뒤 아무 출력이 없으면 Enter 를 한 번 누른다(bash 5.1 이상은 붙여넣은 글을 Enter 를 누를 때 실행한다).
4. 점프 VM 에 B 블록을 붙여넣는다. VM 마다 `---- VM이름`, `== hostname 시각`, 등록된 `# tcgen` 줄이 출력된다.
5. ESX 의 root SSH 창에 C 블록을 붙여넣는다. 마지막에 그 ESX 에 등록된 `# tcgen` 줄이 출력된다.

같은 블록을 다시 붙여넣어도 줄이 늘지 않는다. 케이스를 고쳐 다시 생성하면, 블록에 들어 있는 케이스의 기존 줄을 지우고 새 줄로 바꾼다.

## 5. crontab 에 들어가는 줄

명령 하나가 crontab 한 줄이 된다. 줄 끝의 `# tcgen 케이스이름 호스트` 는 다시 붙여넣을 때 기존 줄을 찾는 표식이다.

```
55 23 19 11 * TC_HOST=`hostname -s`; TC_START=`date +\%Y\%m\%d\%H\%M\%S`; /home/tester/mon/start_mon.sh >> /home/tester/log/mon-${TC_HOST}-${TC_START}.log # tcgen TC-base-a esx01ev01
00 00 20 11 * TC_HOST=`hostname -s`; TC_START=`date +\%Y\%m\%d\%H\%M\%S`; /home/tester/bench/run_a.sh >> /home/tester/log/run_a-${TC_HOST}-${TC_START}.log 2>&1 # tcgen TC-base-a esx01ev01
50 11 20 11 * /home/tester/mon/stop_mon.sh # tcgen TC-base-a esx01ev01
```

- 변수를 쓴 명령만 앞에 `TC_HOST=...;`, `TC_START=...;` 가 추가된다. 등록한 명령은 바꾸지 않는다.
- cron 은 홈 폴더에서 명령을 실행한다. 블록을 붙여넣은 폴더와 관계없다.
- VM 의 cron(cronie)은 명령 안의 `%` 를 줄바꿈으로 처리하므로 VM 줄은 `%` 를 `\%` 로 바꿔 넣는다. cron 이 실행할 때 `\%` 를 `%` 로 바꾼다.
- ESX 의 crond(busybox)는 명령을 바꾸지 않고 실행하므로 ESX 줄은 입력한 그대로 넣는다.
- ESX 시계는 UTC 다. ESX 줄의 시각은 KST - 9시간으로 바꿔 넣는다. 로그 CSV 의 `crontab 시각 기준` 열에 KST 또는 UTC 를 적는다.
- cron 줄에는 연도가 없다. 지난 시각을 넣으면 내년 같은 날짜에 실행되므로 생성할 때 경고한다.

## 6. 확인과 삭제

```
crontab -l | grep ' # tcgen '                                   # VM: 등록된 줄 확인
crontab -l | grep -v ' # tcgen TC-base-a ' | crontab -          # VM: 케이스 TC-base-a 줄 삭제
grep ' # tcgen ' /var/spool/cron/crontabs/root                  # ESX: 등록된 줄 확인
```

ESX 에서 줄을 지운 뒤에는 `/bin/echo root >> /var/spool/cron/crontabs/cron.update` 를 실행한다.

## 7. 제한과 주의

- A, B 블록은 점프 VM 의 셸이 csh, tcsh, bash 중 무엇이든 같은 블록을 쓴다. here-document 끝 줄은 따옴표 없이 쓰고, 본문의 `\`, `$`, `` ` `` 앞에는 역슬래시를 넣어 두었다(셸이 이 역슬래시를 지우고 원래 글을 넘긴다).
- 터미널이 줄바꿈을 CR+LF 로 보내도 된다. 비밀번호 입력 단계는 붙여넣기에서 남은 빈 줄을 먼저 비우고, 빈 입력이면 다시 묻는다.
- 명령에 `!`, 탭, 한글을 쓸 수 없다(한글은 변수 이름에만). csh 가 붙여넣는 글의 `!` 를 이전 명령 불러오기로, 탭을 자동 완성으로 처리하기 때문이다.
- 이름(케이스, 호스트, 명령어 명)은 영문, 숫자, `.` `_` `-` 만 쓴다.
- ESX 를 재부팅하면 crontab 변경이 지워진다. 재부팅 뒤에는 C 블록을 다시 붙여넣는다.
- VM 비밀번호는 점프 VM 의 `~/.tcgen/vmpw` 에만 저장한다(본인만 읽기). 생성기 파일, CSV, 블록에는 비밀번호가 들어가지 않는다. ESX 비밀번호는 저장하지 않는다.
- 비밀번호를 바꿀 때는 점프 VM 에서 `sh ~/.tcgen/setpw` 를 실행한다.
