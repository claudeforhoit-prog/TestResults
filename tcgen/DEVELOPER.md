# 개발 지침 (이 생성기를 고치거나 다시 만드는 사람과 AI 용)

이 문서는 테스트 실행 명령 생성기(tcgen)를 고치는 사람과 AI 코딩 도구가 맨 먼저 읽는 문서다.
사용 방법은 `README.md` 에 있다. 이 문서는 구조, 바꾸면 안 되는 설계 규칙, 고치는 절차를 적는다.

## 1. AI 에게 시킬 때

```
DEVELOPER.md 와 README.md 를 먼저 읽어라.
3절의 설계 규칙은 사용자가 정한 것이므로 요청 없이 바꾸지 마라.
고친 뒤 python -m unittest discover -s tests -v 가 통과하는지 확인하고, 규칙을 바꿨으면 DEVELOPER.md 와 README.md 와 시험을 같이 고쳐라.
```

## 2. 구조

| 파일 | 하는 일 |
| :-- | :-- |
| `tcgen_core.py` | 화면과 무관한 계산 전부: 시각 계산, crontab 줄, 붙여넣기 블록 A~D, 오류 검사, 기록 CSV, 리포트용 CSV, 데이터 폴더 저장과 불러오기. 버전은 `VERSION` |
| `tcgen_app.py` | 화면(tkinter). 탭 1 실행 명령, 탭 2 모니터링 명령, 탭 3 테스트 케이스 표, 탭 4 생성 결과 |
| `run_gui.bat` · `build_windows.bat` | 실행, Windows 실행 파일 빌드(PyInstaller) |
| `tests/test_core.py` | 시각 계산, crontab 줄, 오류 검사, 기록 파일 |
| `tests/test_blocks_shell.py` | 대화형 tcsh · bash 에 블록을 붙여넣듯 보내는 시험(가짜 ssh · crontab) |
| `tests/gui_smoke.py` | 화면을 띄워 버튼을 코드로 눌러 보는 점검 |

Python 표준 라이브러리만 쓴다. 추가 패키지를 넣지 않는다.

## 3. 설계 규칙 (사용자가 정한 것. 요청 없이 바꾸지 않는다)

### 3.1 동작 방식

- 생성기는 명령 글자만 만든다. PC 에서 ssh 를 호출하지 않는다. 사용자가 블록을 복사해 점프 VM 터미널과 ESX root SSH 창에 붙여넣는다.
- 엑셀 파일을 입력이나 저장 형식으로 쓰지 않는다(문서 보안 프로그램이 암호화한다). CSV 와 JSON 만 쓴다.
- 등록한 명령은 바꾸지 않고 crontab 한 줄로 그대로 등록한다. 시작 · 중지용 실행 파일을 VM 에 만들지 않는다.
- 자동으로 붙이는 것은 세 가지뿐이다: 변수를 쓴 명령 앞의 `TC_HOST=…; TC_START=…;`, VM 줄의 `%` → `\%`, 줄 끝 표식 ` # tcgen <케이스> <호스트>`.
- ESX 줄의 시각은 UTC(KST − 9시간), ESX 줄은 `%` 를 바꾸지 않는다.
- 붙여넣기 블록은 csh, tcsh, bash 공통이어야 한다: here-document 끝 줄은 따옴표 없이 쓰고 본문의 `\`, `$`, `` ` `` 앞에 역슬래시. CR+LF 로 붙여넣어도 동작해야 한다.
- 비밀번호는 점프 VM 의 `~/.tcgen/vmpw`(권한 600)에만 둔다. 생성기 파일, CSV, 블록에 비밀번호를 넣지 않는다. ESX 비밀번호는 저장하지 않는다.
- 블록 D(VM crontab 전체 삭제)는 삭제 전에 VM 에 백업 파일을 남기고, 복사 전에 확인을 받는다. ESX 는 대상이 아니다.

### 3.2 테스트 케이스 표

- 케이스 행 아래 VM 행. VM 마다 잡과 모니터링을 지정한다. VM 역할 구분(이름)은 두지 않는다.
- VM 이름 자동 입력 = ESX 호스트 + `vm_prefix` + 두 자리 번호. 새 행은 윗줄 값을 복사하고 시작 시각은 윗줄 + 간격.
- 모니터링 시작 = 잡 시작 전 설정 분, 중지 = 자동(다음 케이스 잡 시작 전 설정 분) · 직접 입력 · 중지 없음.
- '적용' 을 체크한 케이스는 생성에서 빠지지만 시각 계산에는 남는다.
- 리포트용 CSV 의 머리글(`REPORT_HEADER`)은 성능 리포트 생성기의 케이스 정보 파일 형식과 같아야 한다. 한쪽을 바꾸면 다른 쪽도 같이 바꾼다.

### 3.3 저장

- 설정, 명령 목록, 케이스 표는 바뀔 때마다 자동 저장한다. 저장 버튼을 두지 않는다.
- 데이터는 생성기 폴더가 아니라 데이터 폴더(`C:\Users\<계정>\tcgen_data`)에 둔다. 다시 빌드해도 데이터가 지워지지 않아야 한다.
- 읽지 못한 데이터 파일은 지우지 않고 이름을 바꿔 보관한다. 형식을 바꾸면 이전 형식을 읽어 변환하고 원본을 `backup` 에 남긴다.

### 3.4 화면

- 테마는 clam, 색은 `COLORS` 사전 한 곳에서 정한다. 선택한 탭은 파란 바탕 흰 굵은 글씨.
- 명령과 이름에 쓸 수 없는 글자(`!`, 탭, 한글 등)는 생성 전에 오류로 알린다.

## 4. 고치는 절차

1. 고치기 전에 바꿀 파일을 복사해 둔다.
2. 고친다. 동작이 바뀌면 `tcgen_core.py` 의 `VERSION` 을 올리고 `README.md` 를 같이 고친다.
3. `python -m unittest discover -s tests -v` 가 전부 통과하는지 본다. 블록을 바꿨으면 tcsh 가 있는 Linux 나 macOS 에서 실행해 `test_blocks_shell.py` 까지 본다.
4. 화면을 바꿨으면 `python tests/gui_smoke.py` 를 실행한다.
5. Windows 실행 파일은 `build_windows.bat` 으로 만든다.
